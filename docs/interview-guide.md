# 10–15 分钟项目讲解与学习路线

## 讲解顺序

|时间|内容|展示证据|
|---|---|---|
|0–1 分钟|项目目标：模拟设备软件的检测计量闭环；数据与设备都是模拟|README 和系统运行画面|
|1–3 分钟|一次 Die 从移动、采集、算法到保存的路径；控制层独立于界面|架构图、Runner|
|3–5 分钟|C++ 对齐、差分、连通域、线宽边缘计量；真值与独立种子评测|缺陷叠加图、evaluation.json|
|5–7 分钟|跨语言调用；谁拥有图像；为什么使用 SafeHandle|C ABI 与 NativeEngine|
|7–9 分钟|Pause/Stop/Reset 的区别；故障如何结束在途工作|状态图、相机故障与恢复演示|
|9–11 分钟|有界队列与背压；为什么提高吞吐可能增加尾延迟|benchmark.json|
|11–13 分钟|自动测试、1,000 次启停、CI 和发布|测试报告、workflow 配置|
|13–15 分钟|真实问题复盘、验证边界及后续方向|engineering-notes.md|

## 先读哪里

先运行程序，然后按以下顺序阅读：Core 的 Models/Interfaces → EquipmentController → Infrastructure 的 Simulation → NativeEngine 与 C ABI → C++ engine → SqliteResultStore → RegressionTests → WPF ViewModel。

每个模块回答三个问题：输入和输出是什么？它拥有哪些资源？失败或取消时，资源和状态如何收尾？

## 必须能独立回答的问题

1. 为什么相机不能在平台移动时随意并发采集，而采集后的算法可以并行？
2. 为什么队列满时等待，而不是丢掉图像？容量为 8 是否意味着速度一定更快？
3. 为什么 Pause 要等到保存完成？Stop 为什么不能直接 Dispose 所有缓冲区？
4. 输入图像从 C# 到 C++ 是否复制？哪个地方会复制参考图，哪个地方复用工作内存？
5. 调用超时为什么不能证明 C++ 已停止执行？
6. 为什么只有数据库保存成功后才更新“已完成”？结果写入失败时，历史记录可能是什么状态？
7. 缺陷召回率如何计算？如果算法读取真值，为什么评测失去意义？
8. 线宽像素值怎么换算到 μm？为什么这个结果不等于真实设备计量精度？
9. Benchmark 为什么保留串行基线、预热、五轮和逐轮结果？
10. 你亲自运行、修改、调试过哪些部分？还不能独立解释哪些部分？

## 小规模修改练习

- 将队列容量改为 1 和 16，重复基准，解释吞吐和 P95 延迟变化。
- 把线宽容差收紧到 31.9–32.1 px，增加配方边界测试；保持真值独立。
- 新增一个确定性“相机采集超时”故障，先写恢复测试，再实现；不能让停机测试无限等待。
- 为测量 ROI 的位置变化增加一张新配方，验证界面叠加和算法都读取同一份参数。
- 新增一个真实发现的 Bug 回归测试，在修复前确认它失败，修复后记录证据。

## 简历表达

先写已实现的事实：C# 设备状态机、C++ 检测与计量、虚拟设备、SQLite 追溯、故障测试、并发流水线和 CI 配置。性能数字必须取自报告，并说明合成数据和机器条件。尚未上传 GitHub 时，写“配置 CI workflow”，不要写“云端 CI 已通过”。

如果代码借助 AI 完成，可以如实说明辅助方式，并把你能够独立解释、修改和验证的贡献讲清楚。用本项目做准备和练习；正式面试按招聘方的工具使用规则独立作答。
